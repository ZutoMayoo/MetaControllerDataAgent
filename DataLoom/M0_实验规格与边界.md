# DataLoom M0：实验规格与边界

状态：已冻结，等待 M1 实现。

## 1. 本阶段主张

DataLoom 研究的对象是“由项目代码支撑的数据语义理解”能否作为独立能力组件，向 SQL 生成和数据转换任务提供可复核的证据，并在不同任务环境中复用。

本阶段不以完整产品工作台、多用户资源管理或自由规划调度为验收目标。

## 2. 研究问题与实验顺序

| 里程碑 | 问题 | 任务环境 | 通过条件 |
| --- | --- | --- | --- |
| M0 | 公共合同能否覆盖现有任务，而不污染推理/评测边界？ | Code-aware、Spider 2.0-DBT、BIRD | 规格、schema、注册表完成；不改已有 runner |
| M1 | 项目理解模块能否产出可追溯的业务语义证据？ | Code-aware | 生成并校验 EvidencePackage；来源可定位到冻结代码 |
| M2 | 该证据能否提高下游 SQL 结果？ | Code-aware | 完成 A/B/C/D/F 对照 pilot；gold 不进入推理 |
| M3 | 同一接口能否迁移到 dbt 项目任务？ | Spider 2.0-DBT | EvidencePackage 被现有转换链消费；完成分层 pilot |
| M4 | 统一内核能否对纯 SQL 路径保持无回归？ | BIRD | 复用运行记录和 Artifact 合同；项目理解旁路 |
| M5 | 更复杂调度是否有额外收益？ | 由 M2--M4 决定 | 仅在固定路由有效且预算可控后开展 |

## 3. 公共边界

### 3.1 可共享的内容

- 任务身份、资源声明、预算和权限；
- 角色与 Skill 的版本、输入输出和工具约束；
- 可追溯的 EvidencePackage；
- 候选产物、运行记录、哈希和失败状态；
- 推理结束后才运行的独立评测接口。

### 3.2 保留为任务专属的内容

- Code-aware 的源码、fixture、Gold SQL 与执行评分；
- Spider 2.0-DBT 的工作项目、可修改范围、dbt 构建与官方评分；
- BIRD 的 SQLite 数据库、候选 SQL 与宿主评测；
- SQL、dbt patch 与业务结果各自的 CandidateArtifact 细节。

### 3.3 不可跨越的边界

- Gold SQL、validation/evaluation 文件和历史评分不可进入标准推理工作区；
- EvidencePackage 每条 `SUPPORTED` 规则必须绑定源码位置和文件哈希；
- `INFERRED` 或 `UNRESOLVED` 规则不可作为下游的强制约束；
- Verifier 只输出公开资源范围内的证据，不能替代官方评测；
- 官方失败触发 Repair 属于独立探索条件，不并入无评测反馈的标准结果。

## 4. 角色、能力与 Skill

| 层 | 责任 | 首轮实例 |
| --- | --- | --- |
| Tool / capability | 进行确定性操作 | 文件检索、Schema 查询、只读 SQL、dbt 构建、结果比较 |
| Role | 对任务结果负责 | Project Understanding、SQL Generation、Transformation、Verification、Repair |
| Skill | 约束某个 Role 的工作方法 | business-rule-tracing、schema-code-mapping、boundary-and-exception-analysis |
| Controller | 决定何时调用哪个 Role | M1--M4 采用固定规则路由 |

Skill 只能改变已授权能力的使用方式。新增解析器、检索器或数据库操作属于 capability 变更，必须在实验登记中独立记录。

## 5. 统一实验条件

Code-aware 的主实验固定问题、数据库、fixture、SQL Generator、模型、温度、工具集合和预算，只改变生成器获得业务语义的来源。

| 条件 | 业务语义来源 | 目的 |
| --- | --- | --- |
| A | 无代码，仅 Schema/问题/数据库 | 基础能力 |
| B | 人工最小 Oracle evidence | 证据可利用性的参照 |
| C | 完整仓库，由生成器自行检索 | 单 Agent 全仓库基线 |
| D | Project Understanding 输出的 EvidencePackage | DataLoom 主方案 |
| E | D 加项目理解 Skills | Skill 增益 |
| F | B 转换成统一 EvidencePackage | 控制结构化接口的影响 |

M1 只实现 D 的证据生产和 schema 校验，不运行正式模型实验。M2 才运行 A--F。

## 6. 数据集与统计规则

- 数据划分按项目而非题目进行，避免同一代码库与业务规则泄漏；
- 开发、验证与留出项目在配置冻结前明确登记；
- 标准测试条件至少三次独立运行；
- 端到端结果报告执行正确率、可执行率、成本、时间、工具调用、失败类型和置信区间；
- 项目理解结果报告规则准确率、决定性来源命中率、字段映射准确率、无依据规则比例和未解决问题比例；
- 同一任务的条件比较采用配对统计；样本不足时仅报告效应量与区间，不宣称显著性。
