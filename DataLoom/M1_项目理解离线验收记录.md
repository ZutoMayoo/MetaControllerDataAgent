# DataLoom M1：项目理解离线验收记录

状态：完成离线验收；尚未发起模型推理。

## 1. 交付内容

- `runtime/codeaware_adapter.py`：从 Code-aware 任务包生成 gold-free TaskSpec 与项目理解 Prompt；
- `runtime/contracts.py`：校验 EvidencePackage 的来源范围、文件哈希和行号；
- `runtime/validate_evidence.py`：EvidencePackage 命令行验收入口；
- 三个项目理解 Skill：业务规则追踪、代码到 Schema 映射、边界/例外分析；
- `tests/fixtures/snipe-it-supported-rule.json`：只用于来源合同回归的固定 fixture。

## 3. 推理边界验收

适配器发现不同任务包的 `task.md` 既承担用户题目，也可能包含预期答案、Gold、验证说明、fixture 或人工代码证据。若整份文档直接交给 Agent，会破坏实验有效性。

当前适配器只提取题目段落；遇到预期答案、Gold、验收、业务口径、代码证据、fixture 或 validation 标记时停止。它不会向标准 Project Understanding Role 暴露原始 `task.md`、`evidence.md`、`fixture.*`、`gold.sql` 或 `validation.sql`。

这项控制已针对：

- 有独立“预期答案”章节的 Snipe-IT 任务；
- 没有“问题”标题、但在同一行附带预期结果的 InvenTree 任务；
- 问题行内带 `Gold` 字段的 Saleor 任务；

进行回归测试。
